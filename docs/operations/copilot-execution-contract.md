# GitHub Execution Contract

1. Inspect the current repository, branch, issues, pull requests, ADRs, projects, tests, CI, and recent commits before modifying anything.
2. Never assume the repository is empty, duplicate an existing feature, or switch repository, owner, branch, framework, storage engine, or scope silently.
3. Use exactly one scoped issue, one branch from the latest default branch, and one pull request per implementation prompt.
4. Working code, tests, documentation, and migrations are required. Plans, TODOs, prose, and mock-only paths are not completion unless the issue is documentation-only.
5. Use verified stable dependencies compatible with .NET 10 LTS and pin them centrally. Record material choices in ADRs.
6. Preserve Unknown as Unknown. Never turn absence into zero, failure, theft, fraud, non-compliance, or refund entitlement.
7. Never log raw evidence, prompts, credentials, card data, private messages, keys, or decrypted vault content.
8. Personal mode is local-first, offline-capable, network-deny-by-default, and usable without Server.
9. Arabic and English are release-blocking. Every feature is Unicode-safe, culture-aware, RTL-safe, keyboard accessible, and screen-reader addressable.
10. No LLM is the sole judge of a material finding.
11. Do not invent legal text, ECC wording, provider prices, market counts, benchmark results, or compliance claims.
12. Run restore, formatting verification, build, relevant tests, and secret scanning. Record exact commands and results in the pull request.
13. Do not weaken, skip, quarantine, or delete tests to make CI pass.
14. Stop when the pull request is ready for human review. Do not merge, release, publish, send complaints, or enable sharing automatically.
